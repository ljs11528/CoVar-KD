# P14 门槛失败后的补实验计划

日期：2026-10-15。状态：`PLAN_NOT_LAUNCHED`。这是根据已查看的 324 条 P14 结果制定的新计划，不是原协议的成功续跑。原 [门槛协议](utility_protocol_20261015.md)及原结果保持失败。P15 运行前需把本计划中的具体输入、流、源代码、检查点哈希和资源策略登记为独立执行注册；目前没有 P15 实验结果。

## 研究问题与顺序

主问题是局部蒸馏诊断能否指导同一起点之后的训练。先检验观测的可靠性和因果来源，再检验预测能力，最后决定是否训练选择器。soft mIoU 是被比较的一个信号，不预设它优于 CE 或 hard mIoU。Teacher/Shared 的完整因子实验保留为问题背景和机制对照，不继续无目的扩展温度网格。P0/P1 首先是对本项目诊断工具的审查，不能据此声称现有 KD 方法普遍有同一错误；论文贡献需要 P2/P3 对正确匹配诊断的预测能力与适用边界给出新证据。

| 优先级 | 实验 | 解决的问题 | 进入下一步的条件 |
|---|---|---|---|
| P0 | 相同分支重复运行与数值误差测量 | 接近零的方向是否可辨 | 重复误差小于目标对比，否则先提高确定性并修复测量 |
| P1 | BN 前向 × dropout、buffer 与步长拆分 | 训练状态中哪个因素改变诊断 | 在预定重复和种子上重现一个可干预的机制，报告未解释部分 |
| P2 | CE/KD 起点、1/16/128 步探针及 2k 实际分叉 | 短期信号是否预测后续收益 | 新规则在预定同起点续训评估中优于训练模式 CE 探针 |
| P3 | 不同归一化架构的控制 | 是否仅为单个 MobileNet 实现现象 | 跨架构验证或明确收窄 BN 适用范围 |
| P4 | 新种子的最终 80k 比较 | 决策规则是否有实际训练价值 | 仅在 P2 通过后启动，最多 12 个完整 80k 轨迹 |

P0、P1 的前四个锚点只用于工程与机制探索，不能包装成独立确认。预算按阶段释放，P2 失败不启动 P4。P3 对机制的验证可以在 P4 不启动时继续。

保留所有成功、失败和发散记录，先在流内配对，再在训练种子内汇总。禁止删除低分种子。监控统一 eval 前向及原生分辨率，CPU float64 归约四指标和充分统计量。仍以官方完整验证集 hard mIoU 为实际分叉终点，验证标签不能选探针候选。另记录逐类 IoU/CE、预测熵、Brier 分数、按像素及按类的 teacher disagreement；这些属于机制分析，不另立选择门槛。

## P0：先建立数值误差范围

锚点为两数据集、seed1234、20k 与 60k，共 4 个。每个锚点执行 matched_eval 与 matched_train，各执行 c0/c1/c4，每个完全相同分支重复 3 次，总计 72 次一步虚拟更新。全部使用 A 池 256 张，与原 P14 可比较；新增结果单独存放，不替换原分支。

每次从同一模型、BN buffers、动量、梯度、模块标志与 RNG 快照恢复，独立记录更新前后参数摘要、BN 摘要和四指标。测量候选内部重复跨度与 c4−c1 的跨度。将每个数据集、模式、指标的最大同候选终点跨度记为 e，后续诊断中的数值平局带预先定义为 max(5e, 原 10⁻⁶ 容差)。只有重复跨度本身可控才能解释较小差异。这个数值带不是长期改善阈值，不调节到能通过 P2。

若同分支误差覆盖待解释对比，首先在独立工程队列检查确定性算法支持，固定 CUDA 算法及相关设置后重新登记；不能简单丢弃不稳定候选。报告确定性设置的速度开销。

## P1：拆开归一化、dropout 与步长

第一轮只用上述四锚点，确认实现并测耗时；确认轮用两数据集、旧三个训练种子、20k/60k、三个新更新流，共 36 个起点流组合。当前 40k 结果保留在 P14 中，新机制检验固定选早、晚阶段，避免无止境重复整张网格。

在相同完整 batch 下，单独设置学生 BN 使用 running statistics 或 batch statistics，并独立开关实际 dropout/随机模块，形成 2×2 前向状态，每种状态比较 c0/c1/c4。设置具体模块标志，不能用一个 `model.eval()` 同时代替两个干预。需要先枚举当前模型的随机模块与 norm 类型，并验证没有遗漏。

对于 batch-stat 分支，在同一个更新后的参数上分别装回原始 BN buffers 和实际更新的 BN buffers 进行监控，除此之外保持相同。running-stat 分支先证明 buffers 未变，避免把同一终点重复计为两次。再增加不更新参数、只执行对应前向刷新 buffers 的对照。理想计数为每个起点流 12 次参数更新、18 个候选监控终点，加 2 个 buffer-only 终点；确认轮 432 次一步更新、720 个监控终点，另有缓存起点的成本。

主对比是固定 dropout 后，BN 前向干预对 c4−c1 的影响；buffer 干预与 dropout 为预定机制对照。报告每个训练种子内三个流的均值和跨度。若只能在一个锚点解释，不扩大成普遍机制。若 LN 架构后续仍出现现象，进一步解释梯度、随机模块或有限步长，不能继续归因于 BN。

步长控制先只在四锚点、三个新流上做，比较原学习率及其 0.1 倍，分别在 matched_eval/train 下比较 c0/c1/c4，保留各自的 CE 和动量项。这是 144 次一步更新。降低全局 LR 同时改变 CE、KD、动量和 weight decay 的参数步幅，不与只减 KD 系数混为同一干预。只对 matched_eval 的 c1/c4 增加清零动量的机制对照，4×3×2=24 次更新，其 matched momentum 分支复用。Teacher c1 与 Shared_norm 只在这些锚点补作方向/尺度控制，4×3×2 modes×2 conditions=48 次更新，不重跑完整六条件网格。

记录各层参数梯度与相对参数步长、动量范数，以及监控预测的函数变化。旧记录只有整体梯度范数，不能直接推出层级机制。方向导数优先用固定 BN buffers 下沿 KD 方向的有限差分核对，若扩展至监控梯度则独立计成本，不把当前批 CE 余弦当作监控对齐。

## P2：把诊断与实际分叉的目标对齐

先使用两个数据集、三个旧训练种子、20k、CE 与 Shared c1 两种起点，共 12 个状态。每个状态比较 c0/c1/c4。需确认相关检查点已完成源、目的双哈希校验，保留各自真实优化器状态，不能把缺失 KD 起点换成 CE 起点。

探针采用训练模式及三个新流，分别执行到 128 步并保存 1/16/128 步的四指标，36×3=108 个 rollout、324 个监控终点。每个状态、候选的第一个流再完全重复一次，另加 36 个 rollout、108 个监控终点，用 B 池测各 horizon 的重复差异；这些重复只校准数值误差，不计作第四个输入流。128 步的误差不能直接用 P0 的一步误差代替。原来的 eval CE 一步建议只作为独立对照重测，不把旧硬件或不同更新流的结果直接混入。额外 eval 1 步为 12×3 candidates×3 streams=108 次更新。每个虚拟分支结束恢复完整状态，不留下“已经训练 128 步”的主轨迹。

随后每个起点真实分叉 c0/c1/c4，固定续训 2000 步，总计 36 条短续训、72000 次 optimizer 更新，约等于 0.9 个 80k 轨迹的更新数量。按原 80k 日程继续到 22k，不把 2k 当作新的学习率总长度。固定读取 22k 完整验证集 hard mIoU，并保存完整状态。2k 是中期预测检验，不是 80k 最终效果的证明。

预先比较以下决策：eval+pixel CE+1 步；train+pixel CE+1 步；train+soft mIoU+1 步；train+hard mIoU+128 步加重复一致性。最后一种规则以起点轨迹的当前系数为参照，CE 起点为 c0，Shared c1 起点为 c1。替代候选在三个流上都超过当前系数的 hard mIoU 数值平局带才允许选择；多个候选满足时按三流平均 hard mIoU 选，平局保留当前系数，否则选较小 c。数值带取 P0 规则与该状态、horizon 的 5 倍重复最大跨度两者较大值。没有一致证据时保留当前系数。它是待测规则，不预设优于简单 CE 选择；这种按预定公式校准误差不接触后续验证分数。

每条规则必须在读取 22k 验证结果前冻结选择并保存哈希。主质量指标为同起点候选中的选择 regret：候选最好验证 mIoU−所选候选验证 mIoU。这个最好候选仅作事后评估上界，不能用于实际选择。报告全部系数建议、配对排序正确率、regret、拒绝选择比例及开销。分析单位为训练种子，两个起点及流均在种子内汇总。

P4 的资源门槛预先定为：新规则相对 train+pixel CE 的平均 regret 在两套数据均降低至少 0.10 pp，且每套至少两个训练种子方向改善。零差、全拒绝且没有实际改善、仅胜过 eval 对照均不算通过。这仍是实用资源规则，不能写作统计显著。如果 2k 无法给出足够分辨率，允许提出一次预先写明预算的更长检验修订，但不能看完后更改当前判定。

## P3：跨架构验证

优先在 Cityscapes 增加一个不同 CNN 学生 DeepLabV3-ResNet18，以及一个以 LayerNorm 为主的 MiT-B0 学生。运行前检查完整模型，包括分割头，不能因为 backbone 使用 LN 就称整个网络“无 BN”。若头仍含 BN，则登记完整模型的具体 norm 干预，再决定是否需要一个真正无 BN 的控制。

各架构使用新的训练种子 4567、5678、6789，固定 CE 训练到 20k，共 6 条短起点训练、120k 更新；再各分叉 c0/c1/c4 续训 2k，共 18 条、36k 更新。总量 156k 更新约为 1.95 个 80k 更新数量，实际 FLOPs 和时间随架构而异。先复用 P1 的因果控制，再检验 P2 决策的迁移。它检验跨架构机制和中期决策，不冒充完整 80k 方法主表。

模型构建、预训练来源、teacher、分辨率和 head 必须先核对及冻结；当前 Maker 输入不一定包含这两种预训练权重，不能把下载和模型自检当作实验完成。两种新架构不进行新的温度/系数大网格搜索。

## P4：最后才做完整训练

仅在 P2 通过且规则冻结后，使用新的训练种子 4567、5678、6789，在两套数据各比较一个决策规则和一个强固定参照，共 12 个新 80k 轨迹。VOC 固定参照为 CE，Cityscapes 为 Shared c4，选择依据是当前已公开的开发结果。所有新增正式比较在同一 Maker 硬件和 runtime cohort 上执行，旧 3090 三种子结果保留为历史背景。

新规则固定先以 CE 训练到 20k，只在 20k 进行一次冻结的选择，然后把所选系数保持至 80k。P2 的 CE 起点直接对应这个决策，Shared c1 起点是轨迹变化控制。这样不把仅验证过的 20k 探针扩展为未经验证的 40k/60k 多次切换，也避免引入新的选择频率网格。该一次切换方案与 P14 原来先 c1 再多次选择的方案不同，必须独立注册，不把两种训练策略混为同一个方法。

主终点固定为 80k 最终完整验证集 hard mIoU；同时报告各类、全部种子、失败、时间、峰值显存和探针成本。希望看到两套数据均无明显实用退步，至少一套取得稳定收益。若结果仅提升弱固定参照而弱于 VOC CE 或 Cityscapes c4，不能写成已解决选择问题。完整方法的机制消融优先使用 P2 分叉证据；如需新增 80k 消融，需另列预算，不能挤入或隐瞒超过这 12 条的完整训练。

## 新服务器资源、成本与保存

每张卡运行一个独立状态或种子任务，不用四卡 DDP 改动原 batch。四张卡都属于可利用的资源，但每次启动先检查实时进程和空闲显存，保留用户授权的已有保活程序；其他任务占卡时，使用实际可容纳实验的卡。P14 历史共享策略只登记了 GPU0/1 的特定保活身份，不能直接继承为允许共享任何 GPU、任何进程的新策略。P15 需记录当时的实际资源准入条件；空闲 GPU 优先，绝不停止其他进程来凑四卡。

任务按状态和流拆分，以 Cityscapes 分支的实测较长耗时均衡四个 lane，不能简单每个数据集占一张卡。单个任务失败只保留失败记录并核对原因，不换种子，不回退旧服务器。某卡暂不具备显存时，该 lane 等待，其他 lane 继续。

P14 单分支中位耗时为 VOC 9.65 秒、Cityscapes 143.21 秒，主要包含 256 张原生分辨率监控。按这个口径粗算，P0 的 72 分支约 1.5 GPU 小时，P1 确认轮的 720 个监控终点约 15.3 GPU 小时，均未包括起点评分、存取、步长对照及竞争造成的波动。它们是排期量级，不能作完成时间承诺。P2 的 2k 分叉及 P3、P4 必须先用新服务器短基准测训练耗时，再发布总 GPU 小时预算；不同架构不能仅按 optimizer 次数等同成本。

新工作目录使用 `/root/maker/liujinshi/covar-kd/reports/P15_ProbeValidity_20261015` 指向的快盘，归档到 `/root/maker/makerdata/liujinshi/covar-kd/experiments/P15_ProbeValidity_20261015`。代码、注册和结果目录独立于 P14，继承证据只引用不可变科学记录，不把可变 worker/state 文件纳入继承哈希链。快盘不是持久保存承诺，结果、代码和完整状态通过内容寻址顺序写对象存储并做回读 SHA 校验。
