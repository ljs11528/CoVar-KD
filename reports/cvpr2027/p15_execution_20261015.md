# P0/P1 Maker execution registration details

User authorization: execute P0 and P1 on Maker and use all four RTX 4090 cards
where current capacity permits, preserving all existing keepalive programs.
P2 and full training are outside this launch. The P14 gate remains failed.

The [scientific follow-up plan](followup_protocol_20261015.md) is expanded here
into an executable contract, before any formal P15 result is produced.

## Memory and arithmetic

At the first resource inspection, keepalive/Ray jobs occupied about 36--40 GiB
on GPUs 0--2, while GPU3 was idle. They subsequently occupied all four cards,
leaving about 8--9 GiB per card. To preserve the full student batch, saved
backward activations are stored on CPU without dtype conversion using
`save_on_cpu(pin_memory=False)`. Forward and backward still execute on CUDA.
Model updates and monitoring are separate tasks.

The update worker restores the original checkpoint, SGD momentum, RNG and
module flags, executes exactly one full-batch virtual update, and saves its
student parameters and buffers as an ephemeral float32 NVMe state. A separate
worker verifies the file and tensor hashes, loads that exact state, and scores
the original native-resolution monitoring images in eval mode. CPU float64
sufficient-statistic reductions remain the primary metric implementation.
No new full training checkpoint is written, and original checkpoints never
change. The temporary endpoint states remain on fast disk for audit; they
are excluded from periodic scientific-report archives.

Every worker uses FP32, disables TF32 and cuDNN benchmarking, and uses the
original frozen dataset transformations and training settings. No mixed
precision, gradient accumulation or student batch reduction is used. Both
update and scoring admission require 8192 MiB free and cap this worker's
PyTorch allocator at 6144 MiB. Host admission also reserves 16384 MiB per
active update and preserves a 32768 MiB available-RAM floor.
Admission samples twice, two seconds
apart. Every listed compute process must match the explicitly preserved
keepalive command and cwd rules. The scheduler may wait for capacity and may
retry the exact task after a documented resource failure. Other scientific
or implementation failures stop the queue. It never signals existing jobs.

This separation changes execution placement, not the mathematical branch.
It is not claimed to reproduce the P14 observations bit for bit. Native-image
engineering checks precede P0; P0 additionally evaluates one identical saved
training-mode c1 endpoint from each anchor on all four GPUs. These 16 extra
scores measure cross-card variation and remain separate from the 72 formal
optimizer-update replays.

The frozen teacher executes before the student and in inference chunks of
two images. Its CNN uses eval-mode running statistics and performs no
cross-image operation, so chunking does not change the mathematical targets.
Teacher CPU/CUDA RNG preservation is asserted. Engineering checks compare
teacher batch2 versus batch1 logits and compare native versus CPU-saved
activation updates on identical batch2 inputs for each BN/dropout setting.
They also execute the original full student batch under CPU activation
storage before admitting any formal branch. All P15 candidate branches use
this same storage and teacher execution contract. P14 bitwise equivalence
is not assumed. The additional imported `PCOS.py` dependency is also hashed.

## Frozen pools, streams and modules

P0 uses the original P14 full matched batch and its augmentation/dropout RNG
for seed1234 at 20k/60k, both datasets. Pool B excludes pool A and those P0
update images, so all P0/P1 updates can exclude both pools. B selection uses
seed20261016, 256 training images and at least eight images per GT class.
Image bytes, labels, original CE states and runtime sources are hashed before
GPU work. P1 uses the three new streams from the scientific plan.

Module enumeration must find the frozen model's BN and dropout layers and
reject unrecognized stochastic modules. BN and dropout flags are set
independently. Every layer's BN counter is checked: one increment for a
batch-stat forward, zero for a running-stat forward. Before every branch,
parameters, buffers, optimizer, gradients, flags and RNG are restored.

For a BN batch-stat update, original-buffer and updated-buffer evaluations
have identical parameter hashes. Buffer-only forwards preserve every
parameter. Monitoring must leave the full model state unchanged.

## Counts and order

P0 consists of 72 primary one-step replays, plus the 16 separate cross-card
scores. At all eight dataset/stage/mode anchors, the mean c4-c1 pixel-CE
contrast must exceed the numerical band in magnitude. The band is
max(5 times the largest within-candidate replay/cross-card endpoint range,
1e-6), pooled over the registered anchors for each dataset and mode. This
is a measurement-resolution resource rule, not statistical significance.
The other metrics receive their own reported numerical bands. Failure stops
before P1 and preserves all observations for a deterministic-kernel audit.

P1 first executes the four seed1234/first-stream anchor cases as implementation
and mechanism discovery, then the other 32 fixed cases. Those four cases
remain identified as discovery and are counted once. Progression to the
remaining cases depends on engineering validity, not whether a desired
scientific direction appears.

The full P1 factorial has 432 optimizer updates and 72 parameter-free
buffer-only forwards, producing 720 scored endpoints. Original-LR controls
reuse the corresponding factorial endpoints. Thus the nominal 144 LR-control
observations require only 72 additional updates at 0.1 LR. There are also
24 zero-momentum and 48 Teacher/norm-control updates. The complete P1 total is
576 optimizer-update observations, 72 buffer-only forwards and 912 scored
endpoints, including the directional controls below. Resource retries are
retained separately and may increase actual execution counts.

At the four seed1234 anchors and three new streams, for matched eval and
matched train, reuse the CE-updated parameters with original buffers. Form
two diagnostic endpoints theta_CE - delta*lr*g_KD with delta=-0.1 and +0.1,
using the Shared KD gradient at the original state. These 48 endpoints
support central slope and curvature checks around the CE update. They are
finite-difference controls, never coefficients used in actual training.

## Secondary statistics and persistence

Primary pixel CE, class CE, soft mIoU and hard mIoU are tested against the P14
implementation using the same sufficient statistics. Additional pixel/class
entropy, Brier score, teacher-wrong correction/mimic counts and teacher-right
retention are recorded. Teacher predictions are cached losslessly on fast
disk, with their own input and file hashes.

Function change is measured on 256 uniformly sampled valid pixels per image,
with image-index-derived fixed RNG, using normalized float64 log probabilities.
The resulting KL is an equal-image sampled estimate, not the full pooled
pixel KL. This fixed low-storage definition avoids retaining full native
prediction tensors. Baseline samples are archived as separate objects.

Scientific JSON, frozen source, registration and sample objects are stored
sequentially in content-addressed OSS objects/snapshots with full readback SHA
verification. Workers and the detached controller run exclusively on Maker;
the old server is not contacted by this implementation.
